# Frozen D79 support-eight query-order design

Use the eight fresh classes in the audited full-prefix support-eight panel (p1929637 through p2307677), with exact selection/index/audit/module hashes in design-inputs.json. For each class, take the first source prefix at which support-eight rows raise the rank to 39. Form the same pre-eight rank basis from frozen base/direct rows, all support-four through seven rows through that source, and support-eight rows from prior sources. Compute the one-based query position of each exact eight-source row from its latter four support indices and five signs; keep journal order among rows from one query.

Score four predetermined deterministic query orders, each preserving all canonical signed queries and the sign order within a latter-four support: (1) lexicographic latter-four support (existing baseline); (2) reverse lexicographic support; (3) descending minimum of the latter-four support, breaking ties lexicographically; (4) descending sum of the latter-four indices, breaking ties lexicographically. For each order, insert the matching rows as their queries occur and stop at the first verified rank-39 row. Report actual one-based probe position, rank checks, zero-match queries included, and each class's result. Select the order with the smallest sum of probe positions across the eight classes; ties resolve by smaller worst-case probe position, then the above listed order. This is retrospective policy design, not a prospective performance result. Freeze the selected policy and all input hashes before any disjoint holdout source lift. The new holdout will use odd v starting at 1803, after the row-stop panel's last selected v=1801.
