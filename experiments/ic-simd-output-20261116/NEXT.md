# Next preparation candidate, not implemented or measured

The source exposes two separate choices: packed squaring uses two PCLMUL instructions for four canonical n<=32 values but dynamic polynomial reduction; exact constant-polynomial preparation uses four PCLMUL products for the square. A combined packed-square plus exact-constant reduction path may reduce both operations. Current native positive controls report avx2-pclmul128, so a VPCLMUL-only proposal has no positive execution path on this host.

Before implementation, freeze a separate source/protocol and preserve this output-append panel. Factor the already proved constant-fold reduction into a shared const helper, use the packed square raw products with exact constant folding only under admitted canonical bounds, and preserve all wider/unsupported/noncanonical fallbacks. Exact full-map, exceptions/tails/prefix, field-product/square checks and positive packed+constant counters must pass. Inspect assembly and whole-guest instruction counts before fresh native comparison. This is a proposed combination of existing arithmetic specializations, not a novel ECDLP construction or an established speed gain. [pcc:unverified]
