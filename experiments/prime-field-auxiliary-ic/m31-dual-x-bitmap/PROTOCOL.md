# Frozen M31 dual x bitmap screen

The control is the existing 512 KiB direct high-22-bit x bitmap around the 6 MiB sign-packed exact index. The candidate also marks the low 22 bits of every indexed x in a second 512 KiB bitmap and probes the exact index only when both bits are present. The same signed-pair construction, first payload, hash, walk, modular elimination, public target and answer verifier are used in both arms. The candidate is an AND of two necessary membership conditions; exact index equality still decides matches. Its 1 MiB bitmap footprint and extra marking and probe operations are charged.

Before timing, regenerate and verify each frozen 500-point auxiliary and plain basis, dump the complete sorted point-key/first-payload index from both binaries, require byte equality and check the public answer. Compilation and frozen fixture JSON loading precede timing. OS caches are not flushed. Run three seeds, four balanced order repeats each, per basis: 24 matched blocks and 48 fresh-process arms, shuffled with Python seed 112628. Each arm's wall and parent-plus-child CPU window starts before basis regeneration and ends after answer parsing and process exit. Charge input writing, table and bitmap build, relation collection, elimination, and generator answer verification. Preserve all failed/censored arms; require basis SHA-256, entries, trials, relations and answer to match within each block.

Use median paired control/candidate wall and CPU ratios, individual medians, and win counts. Advance to a separate frozen confirmation only if both bases show at least 1.05 paired wall and CPU ratios and at least 8/12 wins for each measure. Otherwise record the negative screen. A local win would be a constant-factor implementation gain on these fixtures, not an asymptotic claim or a proof of runtime. A Lean proof, if warranted, must address the lookup-preservation algorithm; timestamp arithmetic has no role in that proof.
