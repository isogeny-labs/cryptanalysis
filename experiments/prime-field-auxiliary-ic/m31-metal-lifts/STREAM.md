# Local Metal lift-label crossover on fresh coordinates

Build with bash build.sh /tmp/m31-stream stream, then run /tmp/m31-stream 0 and /tmp/m31-stream 1 in this directory. These processes use the existing in-place Metal label shader and fused signed NEON evaluator on Apple M4 Pro. Each paired block gets newly generated canonical coordinates and both endpoints 0 and p−1. Each size rotates through the schedule and arm order alternates. Every output word is compared after both timers stop. Input generation and the benchmark's duplication of input for comparison are outside both timers.

The GPU wall timer includes a new shared allocation initialized with host data, encoding, submission, waiting for completion, and copying all label words back to the vector. The device timestamp covers command-buffer GPU execution. The setup timer includes device discovery, shader-source read, library and pipeline initialization, and queue creation. It occurs once per process, and the OS shader cache may persist. The NEON timer includes its own tail padding, evaluation and truncation. The GPU and CPU run on an unpinned shared machine.

All 14 paired rounds are retained. For a warm summary we chose rounds 2–13 after collecting the data, omitting the first complete cycle in each arm ordering. The headline ratio is the median of within-block NEON time divided by GPU wall time. For a setup-charged comparison at the largest size, sum all 14 rows for that size and add the process setup time once to GPU time. This last quantity attributes the shared setup entirely to that size; it is not a separately run largest-size-only benchmark.
