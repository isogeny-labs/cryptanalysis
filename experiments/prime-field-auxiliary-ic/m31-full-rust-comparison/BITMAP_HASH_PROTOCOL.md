# Frozen M31 512 KiB x bitmap mapping comparison

The candidate is direct x-bit selection in the 2^22-bit x bitmap. Compare three compile-time mappings: the current multiplicative hash (control), the high 22 bits of the 31-bit x coordinate, and the low 22 bits. The same mapping marks and queries a bitmap; the exact sign-packed index still decides membership. Hold the 512 KiB capacity, Rust source, field arithmetic, frozen public auxiliary/plain M31 fixtures, 500-point bases, direct pair rows, validated paired collector, walk, elimination and generator answer check fixed. High/low selection has no theoretical false negatives for marked x values; the complete exact index map and workload identity checks test this implementation on the fixtures.

Compile a separate release binary per mapping. Before timing, regenerate both bases and require byte-identical complete sorted point-key/first-payload maps, a positive bitmap audit of each occupied x, and the expected public answer. Use seeds 0, 1, 2 and five Latin-rotated rounds per seed per basis (30 matched blocks, 90 fresh-process arms). Shuffle blocks with Python `random.Random(112563)`; rotate all three arm orders within each seed. Within every block require equal basis digest, scalar, trial count, relation count, and index entries. Retain failures and censored arms.

Start wall and parent-plus-child CPU clocks before basis generation and charge input writing, process startup, table and bitmap setup, relation collection, elimination, answer verification, output parsing and exit. Compilation, frozen fixture loading and map audit precede timing. OS caches are not flushed. Report medians of paired control/candidate wall and CPU ratios and wins by basis. Select a candidate only if both ratios improve on both bases and complete identities hold; then run a separately frozen confirmation. This is an implementation optimization screen, not an asymptotic or novelty claim.
