# M31 x bitmap capacity sweep

Freeze before timing. Hold the frozen public M31 auxiliary and plain bases, target, sign-packed exact index, one-multiply hash, validated shared-x paired arithmetic, direct pair rows, walk and elimination fixed. Vary only the one-hash x bitmap capacity: 2^18, 2^19, 2^20, 2^21, 2^22 bits (32, 64, 128, 256, 512 KiB). The current 2^20-bit bitmap is the control. Build a separate release binary per size; require byte-identical complete sorted point-key/payload maps, positive bitmap audit for every occupied x, and matched basis digest, scalar, trial count, relation count and entry count in each five-arm block.

Use seeds 0, 1, 2 and five Latin-rotated rounds per seed for each basis, giving every size each process-order position once per seed. Shuffle blocks with seed 112549. Each timed arm regenerates and checks the same frozen 500-point basis, writes the input, starts a fresh Rust process, builds the table and bitmap, collects relations, eliminates and verifies the scalar. Charge wall and parent-plus-child CPU through process exit. Compilation, frozen fixture loading and complete map audit precede timing; OS caches are not flushed. Retain all failures and censored arms. Select a candidate only if it improves paired CPU and wall medians against 128 KiB on both bases with exact identities; then run a separate confirmation panel on the selected size. A small or inconsistent difference is a null result. This is a capacity tuning experiment on one host, not an algorithmic novelty or wider-target claim.
