# Frozen smaller M31 basis screen

After the 1,013-point extension lost cold end-to-end time, test whether reducing the factor base saves more setup and elimination than it adds to relation collection. Use sizes 250, 350 and 500. On auxiliary, each is a prefix of the frozen `s=10` chain's 500 lifted representatives; on plain, each is a prefix of the frozen 500 accepted points. Keep the frozen public M31 curve, generator, target, 512 KiB high-bit bitmap, validated paired collector, direct pair rows, walk and generator answer check. Scale the sign-packed exact index to the next power of two at least half the square of signed-basis length; this preserves its 2^19 slots at size 500 while avoiding an oversized index at smaller sizes.

Compile one release binary before timing. Check the 500-point generated bases against the frozen fixtures and require prefix identity for the smaller bases. Use seeds 0, 1, 2 and six Latin-rotated rounds per seed: 18 six-arm blocks, 108 fresh-process arms. Shuffle blocks with Python `random.Random(112573)`; rotate each basis/size configuration through every position within each seed. Record all failures and censored arms. Require all arms to return the same generator-verified public answer and every accepted relation to pass the Rust point equation check. Different sizes intentionally have different table maps, trials and relation counts.

Charge wall and parent-plus-child CPU from before basis regeneration through input writing, process startup, table setup, relation collection, elimination, answer verification, parse and exit. Compilation and frozen JSON loading precede timing; OS caches are not flushed. Report arm medians and paired 500/candidate ratios by basis, with table, elimination, trials, relations and index entries. Confirm a candidate only in a separately frozen panel before calling it an improvement. Local measurements have pending independent PCC standing.
