# Frozen public-target M31 basis cardinality screen

Test whether increasing the three-summand factor base reduces cold end-to-end cost after paying for its larger pair table and elimination. Keep the frozen public M31 curve, generator, target and scalar check. For the auxiliary construction, compare all 500 lifted representatives from the frozen `s=10` chain with all 1,013 lifted representatives from the same frozen generator at `s=11`. The `s=10` set is contained in `s=11`, and neither contains the generator or target x coordinate. For the plain control, use the first 500 and 1,013 accepted x coordinates under the existing plain generator, excluding the public generator and target and their negatives. This tests basis size and auxiliary-chain extension together; the plain arm helps separate a general cardinality effect from the auxiliary construction.

The modified standalone Rust collector must retain the exact pair-payload convention, validated paired arithmetic, 512 KiB high-bit x bitmap, direct rows, deterministic walk, relation checks, modular elimination and generator answer check. Only input cardinality and the required exact index capacity may vary. Before timing, the 500-point arms must match the frozen public fixture bases and all four arms must check their generated input. Both sizes must return the same public answer. Use seeds 0, 1, 2 and four Latin-rotated rounds per seed (12 four-arm blocks, 48 fresh-process arms); shuffle blocks with Python `random.Random(112571)`. Record every failure or censoring. This screen is exploratory; confirm any apparent gain in a separately frozen panel.

Charge wall and parent-plus-child CPU from before basis generation through input writing, Rust process startup, table setup, relation collection, elimination, answer verification, output parsing and process exit. Compilation and frozen fixture loading precede timing. OS caches are not flushed. Report arm medians, paired same-construction 500/1013 ratios, trial and relation counts, table and elimination times, and answer checks. A candidate improves only if both wall and CPU paired medians favor it on the same target with successful answers; compare the best candidate directly with same-target rho before claiming a distance reduction. Local producer evidence remains unverified.
