# Frozen native M31 flat pair lookup experiment

Hypothesis: the native `PairIndex` pays avoidable HashMap allocation and probe cost to map canonical pair-sum x coordinates to retained entry indices. Test a bounded open-addressed `(u32 x, u32 entry_index)` table with a fixed multiplicative slot hash, power-of-two capacity at least twice the raw signed-pair count, linear probing, explicit empty sentinel, and first-insertion semantics. Keep `Entry` objects and all alternate collision witnesses, pair enumeration, x bitmap, group arithmetic, target walk, relation validation and elimination unchanged. The candidate must handle identity pairs outside the finite-x table and reject capacity overflow. The experiment is a specialized data-structure change, not a new relation family.

Use p=2147483647, E:y²=x³+2x+14, subgroup order 2147505293, G=(1,814455902), and the five public Q in `m31-integrated-local-screen/fresh-public.json`, SHA-256 `dc724fc613d9c2b824b90d59c876f1f7f84b3273d8d607c648e1ba3fbc089252`. `SEEDS.json`, SHA-256 `adc996d6924d44c53f9b8e58b871467e266ca4ecb99faaa7c64e9f5053f4572b`, pins three walk seeds, target IDs, the scheduling seed and exact SHA-256 derivation. Run all five targets x three seeds. Build two binaries from one source commit: native HashMap control and compile-time `M31_FLAT_LOOKUP` candidate. Each binary runs B384 and B512 with m=2, interval base, 64 lanes, pair chunk 64, four million query and five-second online caps. Add matched archived C++ rho on every target-seed block. Shuffle blocks with declared Python 3.13.1 MT19937 seed; rotate five-arm order by `(target_id+seed_index) mod 5`. Fresh process per arm.

Require exact answers by independent public generator multiplication, identical basis, pair counts, work counts and certificate payloads within each hash/flat same-size pair, and independent replay of every IC certificate row and modular cancellation. Save all stdout/stderr, complete raw records, source and binary hashes, hardware receipt, failures, timeouts and incomplete arms. Never discard an arm for timing. The external wall and parent-plus-child CPU window begins before process launch and ends after output parse and independent answer verification. Rust internal phase timings include basis generation, pair-index setup, collection, elimination, certificate replay and report preparation. Compilation and frozen JSON loading precede timing; OS caches are not flushed.

Primary local selection gate: a flat variant must beat its same-size HashMap control on at least 12/15 valid paired blocks in both wall and CPU with median paired ratios at least 1.05, and `flat512` must beat the current B384 HashMap control at least 12/15 with median paired wall and CPU ratio at least 1.15 to justify a B512 cold switch. Report both size-specific comparisons and direct `flat512/hash384`, and the same-panel rho distance. If the gates fail, retain the negative result and remove unselected production code. If they pass, freeze a fresh-seed confirmation before changing the default. This local panel is exploratory until isolated and independently signed performance verification; no Lean theorem about timing is relevant. A mathematical payload proof must establish that replacing x lookup preserves the first retained witness and every alternate witness under bounded probing.
