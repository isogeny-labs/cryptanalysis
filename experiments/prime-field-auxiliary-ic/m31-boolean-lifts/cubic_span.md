# Can a cubic Boolean filter be exact on one entire lift class?

For the field31_s5_base0 curve, let a positive coordinate mean that x³+2x+14 is a square modulo 2147483647, including zero. Represent x by 31 canonical bits. Each polynomial of total degree at most three over GF(2) is a linear combination of the 4992 square-free monomials of degrees zero through three.

Evaluate these features on field coordinates, separating rows by the actual square test. If the rows of one class span all 4992 columns, a polynomial that vanishes there has zero coefficient vector. A polynomial equal to one on the class becomes such a vanishing polynomial after adding the constant one. Thus full rank for both classes implies that every nonconstant degree-at-most-three Boolean polynomial takes both values on both classes. This excludes an exact one-sided filter of that degree over the full field. It gives no running-time bound for higher-degree circuits or filters on restricted inputs.

Run python3 cubic_span.py. The point sequence starts at state 1 and applies the stated linear congruential recurrence before evaluating each row. The Python implementation packs monomials in degree/lexicographic order and removes features containing an absent coordinate bit. It computes square witnesses for the right-hand side or its negative. CubicSpan.lean uses an independent feature construction, appending all monomials containing the next input bit to those omitting it. Lean native evaluation checks both elimination results on the fixed 9989-coordinate prefix. The formal theorem verifies the concrete pivot counts. The implication from full rank to the absence of a nonzero annihilating coefficient vector uses ordinary linear algebra.

The generic span implication is also formalized as vanishes_on_span. The connection between the packed pivot counter and the mathematical span is outside that theorem. An independent PARI quadratic-character count found 4996 lifting and 4993 nonlifting coordinates in the prefix.
