# Can a cubic Boolean filter be exact on one entire lift class?

For the field31_s5_base0 curve, let a positive coordinate mean that x³+2x+14 is a square modulo 2147483647, including zero. Represent x by 31 canonical bits. Each polynomial of total degree at most three over GF(2) is a linear combination of the 4992 square-free monomials of degrees zero through three.

Evaluate these features on field coordinates, separating rows by the actual square test. If the rows of one class span all 4992 columns, a polynomial that vanishes there has zero coefficient vector. A polynomial equal to one on the class becomes such a vanishing polynomial after adding the constant one. Thus full rank for both classes implies that every nonconstant degree-at-most-three Boolean polynomial takes both values on both classes. This excludes an exact one-sided filter of that degree over the full field. It gives no running-time bound for higher-degree circuits or filters on restricted inputs.

Run python3 cubic_span.py. The point sequence starts at state 1 and applies the stated linear congruential recurrence before evaluating each row. The Python implementation packs monomials in degree/lexicographic order and removes features containing an absent coordinate bit. It computes square witnesses for the right-hand side or its negative. CubicSpan.lean enumerates increasing sublists of the 31 positions of lengths zero through three. It packs the columns omitting each bit into a mask and intersects the applicable masks. Lean native evaluation checks both elimination results on the fixed 9989-coordinate prefix. For each computed basis, Lean also checks that all 4992 singleton words reduce to zero. The theorem packed_units_vanish proves that a Boolean evaluator preserving XOR and vanishing on the labeled feature rows vanishes on each singleton. Its proof follows the actual reduction and insertion functions, including empty and out-of-bounds pivots. This implication uses the singleton reductions directly and does not need to infer spanning from the counter. Native evaluation discharges the concrete numerical checks.

The theorem term_coverage characterizes the columns as precisely the increasing sublists of the 31 positions of length at most three. terms_distinct and term_count check uniqueness and cardinality. feature_is_monomial proves that each packed bit is true precisely when every input bit in its column is true. The polynomial is an XOR of a list of distinct selected columns. cubic_annihilator_empty proves that vanishing on either class forces this list to be empty. Native evaluation checks the finite numerical certificates. The theorem lifts_iff_point connects the class label to existence of a y-coordinate satisfying the affine curve equation over ZMod 2147483647, including a zero right-hand side.
