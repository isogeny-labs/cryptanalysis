# Frozen signed-pair orbit hash screen

Use the frozen public p=2^31-1 auxiliary and plain 500-point fixtures, identical target Q, generator, basis regeneration, 512 KiB high-bit x bitmap, fused native paired candidate scan, relation walk, elimination and generator answer check. The control is the current flat-row 12-byte-per-x sign-packed Rust index with two first-payload slots. The candidate stores one `(x, sign, pair-payload)` record per x in an 8-byte slot. It computes only rows with even first signed index and omits odd-first rows. Lookup returns the stored pair for its sign, or flips both adjacent signed indices for the opposite sign. This changes first-payload choice by design while keeping a checked valid relation and exact membership.

Mathematical premise: the signed basis is ordered `B_i,-B_i` in adjacent positions, so `signed[k xor 1] = -signed[k]`. For every pair `(i,j)` with `i<=j`, if `i` is odd, the even-first pair `(i xor 1, j xor 1)` exists in the generated rows and has the opposite sum. Therefore one representative sum and its negation cover both sign keys at the same x, except identity (never indexed). The implementation must handle any self-negating finite point without inventing a second y sign; the odd prime-order subgroup excludes nonidentity two-torsion on these fixtures.

Preflight: prove the signed-index orbit coverage as a Lean theorem with explicit premises about the sign involution and group negation, without claiming Rust or C++ refinement. Then independently enumerate the full control key set and the candidate key set, require identical keys and entry counts, and check every candidate payload by the Rust group law. Audit full solves for seeds 0,1,2 on both bases, comparing lookup *presence and first signed scan index at each walk state*, while allowing pair payload, elimination path, relation count and solve trial to differ. Every accepted relation and final scalar must verify. A key, presence, relation or answer mismatch aborts timing.

Timing: three seeds 0,1,2, eight balanced order rounds per basis, shuffled by `random.Random(2026112611)`, for 48 paired blocks and 96 fresh-process arms. Charge wall and parent-plus-child CPU from before basis regeneration through process exit, including table/bitmap setup, native scan, relation collection, elimination, answer verification and output parsing. Require identical basis digest and table key set per pair. Preserve raw rows, failed/censored arms, phase timings, slots and native calls. Report medians of paired candidate/control wall and CPU ratios and wins separately by basis. A positive first panel needs a separately frozen fresh-seed confirmation before adoption and a matched rho comparison before any crossover claim. Lean proof of orbit coverage is a correctness premise, not a performance theorem.
