# Batch inversion of 64 M31 field elements

This local arithmetic benchmark compares direct exponentiation per element, one inversion per batch using serial prefix products, and one inversion per batch using a balanced binary product tree. The batched methods replace zero leaves with one for the product and emit zero in the corresponding output slots. Both use the same multiplication and root-inversion implementations. With 64 nonzero elements, both batched methods perform 189 field multiplications outside the single root inversion. The tree has six levels each way, which exposes more independent multiplications.

On one shared Apple M4 Pro, the median paired prefix/tree time ratio was 1.838 [1.823, 2.179] with nonzero inputs and 1.825 [1.779, 2.061] with each input independently zero with probability 1/16. Intervals are descriptive 95% block-bootstrap intervals within this panel. Median tree time per element was 2.624 and 2.626 ns respectively. These are measurements of the standalone kernel. The archive already uses serial batch inversion, and there is no pipeline timing in this panel.

Each measured block contains 2,048 independent batches of 64 elements. The 36 blocks alternate nonzero and mixed inputs. All six method orders occur six times across the panel. For each call the program checks canonical range and either zero output or input times output congruent to one, using ordinary integer remainder as an independent check. Validation runs after the clock stops. Constant batches of zero, one and p−1 are covered before warm-up.

Compile with Apple clang++ using `-std=c++17 -O3 -mcpu=native`, with assertions enabled. Run the executable to emit the CSV. Columns are block, method (0 individual, 1 prefix, 2 tree) and wall nanoseconds. Run `python3 analyze.py` with NumPy to summarize the archived rows. Lean 4.28 and matching Mathlib check Tree.lean. The allLeaves theorem covers arbitrary binary shapes and zero placement in a field. The C++ buffer layout and compiled instructions are tested empirically.
