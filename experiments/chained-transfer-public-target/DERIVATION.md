## Exact source order and public input

The P1 constructor is the original N4 q223/seed1 constructor. The original
FpR implementation independently checks its exact binomial modulus for
irreducibility. A basis-product comparison identifies the two explicit
polynomial-basis fields; a Frobenius comparison is an additional control.
This is not an identification of arbitrary equal-size field encodings.
[pcc:unverified]

Write the elliptic source as `w²=v³+a2*v²+a4*v+a6`. In characteristic greater
than three, put `X=v+a2/3`, `Y=w`,
`A=a4-a2²/3`, `B=a6-a2*a4/3+2*a2³/27`. Direct expansion gives
`Y²=X³+A*X+B`. The polynomial identity is also stated with cleared
denominators in `PublicTargetBridge.short_model_cleared_polynomial`.
The independent original curve engine checks smoothness, that G is nonzero
and on this actual short model, primality of ell, and ellG=O. [pcc:unverified]

For a nonsingular elliptic curve over F_(q³), Hasse puts its order in
`[q³+1-floor(2sqrt(q³)), q³+1+floor(2sqrt(q³))]`. Since nonzero G has prime
order ell, Lagrange says ell divides the group order. If that integer interval
contains exactly one multiple of ell, it determines the order. P1 requires
that this is 4ell. With ell>4 the ell-Sylow subgroup then has order ell, so
on-curve Q with ellQ=O lies in the unique subgroup generated by G. This avoids
using an ell-annihilation check alone when rank-two ell-torsion could exist.
If the unique-multiple test fails, the constructor reports the gap instead
of promoting an order certificate. No numerical q223 outcome is assumed by
this argument. [pcc:unverified]

## What removing the witness changes

The original IC body uses its scalar parameter once, to construct Q, then
performs the relation/LA/descent and verifies k_found*G=Q. The literal public
derivative replaces that parameter with a point and removes that construction.
The original plain-rho derivative has the same interface change. No random
stream, relation, matrix, descent or verification body is changed. Target
generation belongs outside either actual solver interval. Moving it is an
accounting correction, not a new algorithm or measured improvement.
[pcc:unverified]

The witness residues occur only in the test harness, which generates public

checks every IC answer. The original rho return type does not expose its
recovered scalar; its independent answer replay remains an explicit separate

## Basepoint changes: distinguish a class key from a degree-six input

Let C be the SAME smooth plane quartic and K_C its canonical divisor class.
For a rational basepoint P, the original canonical degree-three reference is
`Dinf_P ~ K_C-P`. A typical key for a length-three divisor D represents
`[D-K_C+P]`; an exceptional key for R represents `[P-R]`.

Set `delta=[P_new-P_old]=Exc_new(P_old)`. Reinterpreting the SAME raw typical
or exceptional geometric key at P_new changes its class by +delta. Therefore
the SAME actual old class is represented in the new group by
`raw_new(key)-delta`. In particular old zero, whose key is Exc(P_old), becomes
`delta-delta=0`, not raw Exc_new(P_old). The correction is geometric; it is
not inferred by fitting scalar samples. Faithful canonical reduction is a
concrete bridge required in addition to the additive identities.
[pcc:unverified]

A degree-six cubic-space input is different. Its raw reduction represents
`[D6-2*Dinf_P]`. Reducing the SAME degree-six input at P_new changes its class
by **2delta**. This does not contradict the +delta rule for a final canonical
degree-three key: reduction changes the representative divisor. In general a
degree3m input normalized by m*Dinf has reference shift m*delta. A test that
copies final keys must use delta; a test that re-reduces original cubic spaces
must account for 2delta. Subtracting the two actual origin fibres cancels that
raw degree-six offset. [pcc:unverified]

## The two quartic ordinate conventions

Let the common genus-one quartic be
`H: y²=t⁴+a*t³+b*t²+c*t+d`, smooth in characteristic greater than three.
Put `B=a/2`, `s=(b-B²)/2`, `alpha=c-2*B*s`, `beta=d-s²`.
The completed adapter uses
`x=2*(y+t²+B*t+s)`, `Y=2*x*t+B*x+alpha`,
`X=x+(B²-4*s)/3`. Its positive quartic infinity is the elliptic origin.

The original N4 formulas instead give
`v=2*t²+a*t-2*y`, `w=2*t*(v+2*s)+c+B*v`.
Evaluate the completed formulas at **-y**. Direct calculation gives
`x=v+2*s`, `Y=w`, and `X=v+b/3`. Thus the short-model isomorphism
`I(v,w)=(v+b/3,w)` corresponds to reflecting the quartic ordinate. It does
not identify the two pointwise cover maps with the SAME ordinate. N4's
Weierstrass infinity corresponds to negative quartic infinity, which this
reflection sends to the completed positive infinity. The group isomorphism
extends across the exceptional finite charts and both infinities by the
smooth projective genus-one construction; these extensions remain explicit
concrete obligations. [pcc:unverified]

There is a useful geometric sign test. Let kappa:H→E_new identify positive
infinity with O, let iota(t,y)=(t,-y), and let T=kappa(infinity_minus).
For a finite t0, the actual divisor of t-t0 is
`P+iota(P)-infinity_plus-infinity_minus`, with ramified multiplicities
retained. Hence `kappa(iota(P))=T-kappa(P)`. At the two infinities the same
identity is immediate. T is not assumed to have order two.

Let lambda:H→E_old be the N4 map. The finite polynomial identities and the
origin identification give `I*lambda=kappa*iota`. Consequently
`kappa(P)-T=-I(lambda(P))`. This fixes the sign of the degree-zero divisor
map, rather than guessing it from equal coefficients or j-invariants.
[pcc:unverified]

For the completed trace pullback Phi_new and the original N4 degree-zero
trace pullback Phi_old, it follows that
`Phi_old = Phi_new composed with S`, where **S=-I**. An actual adapter to the
old source must use this sign or prove an equivalent origin-normalized
convention. After transporting the norm back by S^-1,
`S^-1 * norm_new * Phi_old = [2]` on the admitted source subgroup. This uses
the actual completed norm/pullback identity from the parent, not an inverse
point map. Concrete same-curve/field/fibre/reference checks are still needed
before applying this conditional argument to the generated fixture.
[pcc:unverified]

## Why the legacy three-class descent cancels the origin

Suppose the raw transfer values have form `h(P)=Phi(P)+b` in the actual Picard
group, where Phi is the admitted additive transfer and b is the geometric raw
origin. For a random source R, the original descent obtains logarithms of
`h(R),h(R+G),h(R+Q)`. For an additive relation-log functional L into F_ell,
their differences are `L(Phi(G))` and `L(Phi(Q))`. If Q=kG and the first is
nonzero, the ratio recovers k. Both the constant b and the common model sign
cancel. The original code explicitly rejects a zero denominator and verifies
the recovered answer on the source. This argument does not prove that its
relation kernel yields a valid nonzero functional, or that descent succeeds;
those are separate original-solver/native obligations. [pcc:unverified]

The formal `three_affine_log_ratio` statement exposes the three affine values
and the inverse of the denominator. It proves their algebraic ratio without
assuming the final recovered equality. The actual Picard/log construction and
its geometric origin/sign are not encoded merely by that ring lemma.
[pcc:unverified]
