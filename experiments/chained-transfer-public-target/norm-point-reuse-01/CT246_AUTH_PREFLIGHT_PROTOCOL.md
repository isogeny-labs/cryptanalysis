# CT246 — read-only credential versus object-access discriminator

Date: 2026-11-19. Status: preregistered diagnostic, **not an ECDLP measurement**. [pcc:unverified]

## Why this diagnostic exists

The owner-priority original 695/701-record Jacobian norm-reuse replay is currently blocked before compilation. On [CT245 CI #44622872809](https://github.com/isogeny-labs/cryptanalysis/actions/runs/44622872809), original blob and deterministic source guards passed but the approved `nondual-models-18` S3 hydration returned `HeadObject 403` for three first attempted content-addressed keys. The prior [CT137 CI #43722363285](https://github.com/isogeny-labs/cryptanalysis/actions/runs/43722363285) hydrated all six original files and typechecked the uninstrumented original/CT125 packages. Both jobs were GitHub-hosted Ubuntu 24.04 on runner image `ubuntu24/20261111.370`; each injected GitHub Secrets under the same variable **names**, used the preapproved artifact store and pinned hydration code. These observations do **not** establish that the underlying credential value, cloud principal, permissions or object state stayed constant.

## Frozen bounded test

1. Trigger only for a same-repository `pull_request` modifying the separate `ct246-original-artifact-auth-preflight.yml` workflow. Use `ubuntu-24.04`, `permissions: contents: read`, a **five-minute** job and no source checkout or EKS/Spot cluster. No write to S3, no model download, no `ListBucket`, no IAM policy changes and no alternative model source.
2. Using only already-declared `ARTIFACTS_AWS_ACCESS_KEY_ID`, `ARTIFACTS_AWS_SECRET_ACCESS_KEY` and `ARTIFACTS_AWS_REGION`, check whether nonempty credentials were injected, run `aws sts get-caller-identity` with stdout/stderr suppressed, and test exactly **one** original approved `s3api head-object` key: bucket `setec-astronomy-artifacts`, key `store/sha256/22/22225094b7e3727332a761593b47ac44a2efd2f04bbdb1b1865abf3c35ba7267`. This is a read-only existence/access check against the existing immutable manifest, not an attempt to reconstruct missing data.
3. Emit only `credentials_present`, STS exit status + coarse error class, and HeadObject exit status + coarse error class. Do not print credential values, account ID, principal ARN, request headers or unredacted AWS stderr. No output file containing raw credentials.
4. Outcome mapping: (a) missing environment variables => GitHub secret exposure/admission problem; (b) STS succeeds and HEAD receives 403 => credentials are accepted by STS but access to that object is forbidden *or* its existence concealed (not proof the key exists); (c) STS authentication failure => credential/endpoint problem; (d) STS authorization failure but HEAD 403 => ambiguous, do not infer principal validity; (e) HEAD succeeds => access appears restored for **one** key only; rerun unchanged six-object authenticated CT245 after approved review. Any 404 or other error remains classified without guessing causality.
5. No retry loop. Do not alter CT245's SHA/length checks, original blob guard, runtime, original 695/701 fixture or stopped native execution. A passing diagnostic step is **not** a passing original model hydration, native compilation, cost result, ECC solver result or signed PCC.

**Reproducibility:** inspect the exact PR head's `.github/workflows/ct246-original-artifact-auth-preflight.yml` and the single corresponding Actions run. Cross-check reported classification with the pinned CT245 failure, not with any fabricated replacement fixture.
