## Algorithm and bounded execution

The candidate and baseline use the **same** 32-partition random-adding affine rho routine with 300,000 steps per attempt and at most 6 attempts. Source uses the quotient by +/-1; target uses +/-1, +/-lambda. All-state collision memory and trap escapes are charged. Each cold solve derives fresh jumps from public G,Q and verifies the recovered scalar on the source curve. It has *no access* to the planted scalar during solving.

A development panel of 8 public logarithms (seed 20261115) was used to debug the new mechanism; a separate 8-case BSGS screen showed inconsistent/no stable advantage. Both are excluded from confirmatory reporting.

The two holdout cohorts each contain **64 different public targets**, generated by Python random.Random(20261116) and random.Random(20261117), scalars drawn from [q//8, q-1). Method order is ABBA/BAAB on alternating targets, two independent timed observations per arm. Frozen quantities: raw ns, group additions/inversions, iterations, fruitless cycles, stored points, RSS; exact recovered scalar and independently recomputed public points.
