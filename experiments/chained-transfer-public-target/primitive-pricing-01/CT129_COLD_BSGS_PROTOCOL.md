# CT129 — preregistered single-target BSGS screen

Status: experimental protocol, NOT a measured ECDLP advantage. [pcc:unverified]

**Question.** For the fixed alternative three-model prime-subgroup instance at q=223, ell=2,771,711, can direct degree-169 elliptic isogeny followed by a *cold* destination BSGS solve be faster than a *cold* source BSGS on exactly the same public (G,Q)? This is an intentionally **optimistic lower-work proxy** for a full Jacobian route: omits Jacobian class admission, correction, halving, full-group norm and certification; their costs are nonnegative. It cannot establish that the complete transfer is faster. The original-source prime 2,773,073 must NEVER be substituted.

**Frozen inputs.** Use the supported fixed-nu12 model 0 and model 2 in `chained-n4-fixed-jacobian-chain-evaluator` from the parent branch. Use the full-degree-169 rational map from `Runtime.setup.actual_composite_certificates`, source 0 -> target 2. Derive nonzero prime-order source generator G=[4]G0, verify [ell]G=O, and take the same five public targets Q=[m]G, with m in (1, 2, 17, 12345, ell-1). The planted scalar is known to the test harness for **post-solve validation only**; the solver accepts only (G,Q,ell) with no scalar hint. The nontrivial cases are the scientific timing cohort; m=1,2 are controls.

**Algorithm.** Independent cold BSGS using a freshly allocated table for every query on the source F_(223^3), and the same algorithm after mapping BOTH G and Q with the actual degree-169 rational map to the quadratic F_(223^6) destination. Guard nonsingular curves, mapped point order, output membership, all source and destination scalar identities and re-verification against the *source* public Q. Neither case may reuse a prior baby's table. The target timings must include both rational-map evaluations and both destination BSGS phases. Record separate native setup/constructor cost and peak RSS; keep the setup excluded warm proxy clearly separate from cold-complete cost.

**Measurement order.** Before any admitted native timing: compile and run exact source with pinned Rust and offline dependencies, pass all five point/equality/known-answer tests including m=ell-1. Collect isolated same-host source/target ABBA pairs over at least four complete blocks, and an A/A control, raw per-query nanoseconds, process/source hashes, memory and machine information. A single process times solver arithmetic only: actual runtime construction is reported separately. Report confidence intervals from **blocks**, not fake independent point samples; control cohorts do not enter the main ratio. Expected result may be a loss. No GPU/Spot/pod without approved budget admission. Never infer a full Jacobian or optimized-rho/IC win from this BSGS screen.

**Pass/fail.** Every recovered scalar must match the planted answer mod ell and independently satisfy [m]G=Q on source. A bad modulus, wrong mapped point, missing output, bad repetition count, changed source cohort or mismatched public input rejects. Any target advantage must still beat the stronger matched optimized rho, BSGS and existing index calculus with complete setup/transfer/class corrections/norm/LA and memory included, independent replay, CI and PCC signature. Otherwise it is only a conditional substage result.

**Prior art reviewed.** Existing [CT35 cold-isogeny BSGS audit](https://github.com/isogeny-labs/cryptanalysis/pull/1500) found source BSGS cheaper in all counted F101 field primitives, but did not benchmark this fixed nu12 curve. [CT126 pricing](https://github.com/isogeny-labs/cryptanalysis/pull/1534) measures map primitives but not any DLP; [root #3877](https://github.com/isogeny-labs/crypto/pull/3877) records 695/672 whole-population reuse. The degree-169 map is classical isogeny arithmetic: [Bostan–Morain–Salvy–Schost (2008)](https://arxiv.org/abs/cs/0609020). Shared research-KB MCP and checkout-local fallback were unavailable in this runtime; lead-atlas is available only as prior PR references. No novelty claim.
