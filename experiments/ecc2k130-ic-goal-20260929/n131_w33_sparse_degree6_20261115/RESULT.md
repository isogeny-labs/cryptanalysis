The sparse numeric-pivot kernel processed **4,752 of 78,076** exact degree-six rows on the frozen N131 W33 public code block in 187.8 seconds of child work. Its prefix rank was 4,752 with zero dependent rows, 47,915,805 stored monomial words, and 392,691,712 B child `ru_maxrss`. This run supplies a bounded public-arm prefix for a reducer that omits row-combination tracking; it does not deliver a complete block decision under the frozen wall envelope.

## Exact source and method

The curve is `EC1N131Ckb1heb5f1998f20b` over `GF(2)[u]/(u^131+u^13+u²+u+1)` with `y²+xy=x³+1`. The W33 source uses seed mask 898618, two free left-code bits and all 32 right-code bits. The [prior exact eliminant](../n131_w33_freecode_resultant_20261018/RESULT.md) has 13 field terms; both frozen target rows expand to 1,619 squarefree Boolean ANF terms of degree at most four. The positive row contains the known code pair `(3,16722)`; the second row uses the archived ordinary raw public point. All 131 field-coordinate equations are exported to [two exact input files](prepare_result.json), whose hashes are bound before execution by [the run protocol](run_protocol.json).

Multiplying each coordinate equation by every Boolean monomial of degree at most two produces 596 factors per equation and **78,076** rows over **1,676,116** possible degree-six columns. The exporter records 106,259 and 105,812 source-coordinate monomial incidences; before Boolean cancellations the degree-six row streams contain 63,330,364 and 63,063,952 incidences. `sparse_degree6.cpp` generates one row at a time, cancels duplicate monomials, and reduces it against stored sparse pivots. It checks whether the constant-one row lies in the generated span only at its terminal boundary. The [proof map](PROOF_MAP.md) links the existing Lean certificate theorem and prior curve/source audits; this run found no certificate on its processed prefix.

## Prior sparse reducer and exact workload identity

The [earlier streamed sparse degree-six reducer](../n41_n131_sparse_block_macaulay_20261019/RESULT.md) already established bounded sparse storage for this W33 block. It retained row-combination IDs, reproduced five N41 exclusion certificates, and reached a last reported 17,000 independent N131 constructed-positive pivots at its 590-second cap with 1,107,935,232 B sampled combined RSS. Its positive-first gate left the public arm `GATED_BY_POSITIVE_CAP`. The present numeric-pivot implementation uses 64-bit monomial masks and omits row-combination tracking; it ran the public arm after its own positive cap. The different arm, row order, combination tracking, cap, and memory boundary prevent a controlled speed or memory ranking between the two implementations.

The two N131 exporters have different text formats, so their file SHA-256 values differ. A coordinate-by-coordinate set comparison of their monomial masks found **zero differing coordinates in either arm**: both constructed-positive files have 131 equations and 106,259 support entries, and both public files have 131 equations and 105,812 entries. The comparison parses the earlier `n131_t{0,1}_a0.eqs` lines as `coordinate count masks...` and the current `equations_{0,1}.txt` lines as `count masks...`, then compares each coordinate's mask set. The [earlier preparation receipt](../n41_n131_sparse_block_macaulay_20261019/prepare_result.json) and [current preparation receipt](prepare_result.json) identify the source files and counts. This establishes exact input-system identity for the comparison, while preserving each reducer's separate execution record.

The first supervisor invocation through system Python stopped at `psutil` import before launching a child; [its failure](first_attempt_error.txt) is retained. The same frozen source then ran through the checked repository Sage launcher after saving [runtime information](sage_runtime_info.json). `python3 verify.py` checks all source and artifact hashes, both censored statuses, caps, and public-prefix counts. The source exporter took 0.451 seconds outside the child reduction intervals.

## Search decision

The measured public prefix covers **6.09%** of the required rows at the parent cap, with substantial pivot fill and no dependency so far. The remaining rows and constant-one membership are unknown. Both sparse implementations establish bounded-prefix feasibility; another storage-only variant has a weak cost case. The next candidate should instead supply a sound factored elimination, a row-selection rule with an explicit certificate-completeness condition, or a target-conditioned relation across enough free source slots to preserve ordinary-target coverage. Preserve the unpinned N41 relation control and the N131 constructed witness when testing that change.
