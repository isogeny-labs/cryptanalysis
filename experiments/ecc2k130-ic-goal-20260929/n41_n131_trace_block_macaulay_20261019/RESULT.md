# Dependency-traced block reduction

The dependency-traced degree-six reducer reproduced the five exact N41 block exclusions and retained the public-relation block, with **1.32–1.74× shorter N41 cell wall times** than the preceding sparse implementation on the same equation files. On the frozen N131 constructed-positive block it reached the same 17,000-row checkpoint at **536.147 s**, 14.126 s earlier than the preceding implementation, then ended at the same **590 s `WALL_CAP`**. Its sampled combined peak RSS increased from 1,107,935,232 B to **1,314,586,624 B**. These are ordinary-host component observations; the N131 public block remains `UNKNOWN_search_cap` behind the positive-first gate. This is a point-decomposition component, so `candidate_id: null`.

The [preceding experiment](../n41_n131_sparse_block_macaulay_20261019/RESULT.md) defines the exact `EC1N41Ckb1h7d5e80d3c4d0` and `EC1N131Ckb1heb5f1998f20b` field representations, curve, W11/W33 source encodings, target rows, and 13-term two-product eliminant. This run used those byte-identical `.eqs` inputs, whose complete coefficient supports were independently reconstructed by the checked Sage audit in that archive. The [N41 protocol](query_protocol_n41.json) fixed six cells, one worker, 120 s per cell, and 4 GiB RSS before launch. After its certificates passed independent replay, the [N131 protocol](query_protocol_n131.json) fixed the constructed-positive cell followed by the public raw-point cell, one worker, 590 s per cell, 4 GiB RSS, and a positive-first gate. Both protocols hash the executable, source, inputs, and prerequisites. [Build metadata](build_result.json) records the compiler and flags.

The previous reducer stored a fully expanded combination of original equation rows at each pivot and XORed those combinations during every reduction. This reducer stores, for each pivot, its original row ID and the earlier pivot IDs used to reduce it. On a constant-one row it expands that acyclic dependency graph once, in reverse pivot order, and prints original `[field_bit, multiplier_mask]` pairs. The row supports and pivot order are otherwise identical. The five N41 certificates contain exactly the same 696, 767, 679, 768, and 751 original rows as before and independently replay to constant one. The [proof map](PROOF_MAP.md) gives the reconstruction invariant and the checked certificate-soundness theorem.

The N131 last progress line reports 17,000 independent pivots out of 78,076 requested rows, 4,703,012 row reductions, a largest intermediate row of 56,535 monomials, and a longest current dependency trace of 6,796 pivot IDs. The previous implementation had the same pivots and row reductions at this checkpoint; its longest fully expanded combination was 7,109 original row IDs. The 17,000-row value is a last emitted checkpoint, not an exact terminal row count. At matching checkpoints the trace run lagged until approximately row 15,000, so its small N41 timing improvement did not transfer uniformly. The trace's extra retained dependencies cost about 207 MB sampled combined RSS at the cap, while the modest late time saving was insufficient to complete the positive block.

`python3 verify_n41.py` checked all six statuses, prior expected root/exclusion outcomes, resource receipts, hashes, and five exact certificate replays. `python3 verify_n131.py` checked the frozen prerequisites, positive-first gate, cap receipt, logs, and hashes. Both passed and their stdout/stderr are retained. These checks support the specific block decisions and bounded prefix; they do not estimate natural relation yield or full target recovery.

The next experiment should attack the dominant sparse row XOR cost directly, while keeping certificate replay exact. A concrete comparison is an adaptive packed representation of row supports, with sparse and bitset containers selected by measured density, and a separately bounded N41/N131 prefix benchmark on the same frozen inputs. Its memory gate must include all pivot containers, monomial indexing, and trace data. If the N131 positive completes, the protocol should then run the public block and only promote a verified ordinary relation to the factor-base collection and rank gates.
