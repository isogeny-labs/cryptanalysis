# Proof map: affine-hull rejection and finite rank

The exact mathematical implication used here is: for a finite coordinate set `S` in `GF(2)^n`, every `x∈S` lies in `s₀+span_GF(2){s+s₀:s∈S}`. If the difference span has rank `n`, this affine hull is all of `GF(2)^n`, so the linear screen accepts every target coordinate. The first statement follows by choosing the difference `x+s₀`; the second follows from the dimension theorem for an `n`-dimensional binary vector space. The filter is necessary for an exact coordinate match, but an affine survivor need not be an actual point sum.

The prior [ThreeCodeSign.lean](../n41_w8_three_code_family_screen_20261015/ThreeCodeSign.lean) proves, under simultaneous-sign invariance, that 32 canonical choices cover every x output of a three-pair family. It was rebuilt here with pinned Lean 4.34.1; [lean_reuse.log](lean_reuse.log) reports no axioms for its first two theorems and only standard `propext` and `Quot.sound` for its covering theorems. The present checked-Sage producer verifies exactly 32 distinct x coordinates for each of the selected N41 and N131 code triples, constructs them with the actual curve group law, and confirms the positive residuals. The independent Sage auditor uses `GF(2)` matrices instead of the producer's integer XOR pivot reducer; it checks every saved prefix rank and all target membership decisions.

The empirical rank sequence is a finite-field computation, not a new abstract rank theorem. A full Lean proof of the concrete N41/N131 sequence would require definitions of the specified binary fields, elliptic group addition, the archived source states, and a kernel-checked bridge from those operations to the saved coordinate matrices. Those objects are not formalized in this module. The checked generic 32-output bound and the written affine-hull argument are separated from the independently replayed finite ranks; no arithmetic certificate is presented as a full curve-level Lean proof.

The reused Lean module was checked with `elan run leanprover/lean4:v4.34.1 lean` and its actual source path. `lean4checker --fresh` was unavailable on this host.
