# Proof map for quotient Euclid source-code gate

The readable soundness argument is in [RESULT.md](RESULT.md), with exact
input laws and the squarefree allowed-code polynomial. The pinned Lean
toolchain is `leanprover/lean4:v4.34.1`; the checked module is
[`EuclidSoundness.lean`](EuclidSoundness.lean).

| Result | Lean declaration | Exact assumptions | Status |
| --- | --- | --- | --- |
| A Euclidean remainder stays in the ideal generated by `H,L` | `QuotientEuclid.remainder_generated` | Commutative ring; both operands already in the generated ideal; exact division identity | Checked |
| A unit Bezout certificate excludes a specialized common root | `QuotientEuclid.unit_certificate_rejects` | Commutative source and nontrivial target rings; additive and multiplicative specialization; maps one to one; certificate equals one | Checked |
| A nonunit-pivot factor split covers each allowed code | `QuotientEuclid.split_covers_root` | Factorization of active code polynomial; multiplicative specialization to a domain; code root of active polynomial | Checked |
| Every rejected source code has no common root of the concrete N41 `H` and `L_V` | Composition of the above with `run.cpp` | Squarefree `G`, exact field implementation, leading-coefficient inverse, every executed Euclid step and its specialization | Partial: the Lean module does not encode the concrete polynomial arrays or prove the C++ trace is a Bezout certificate |

semantic map for `R[r]`, plus a replayable trace of pivot inverses,
divisions, and source-code factorization from the native gate. The frozen
finite-code oracle currently checks the resulting hit set independently.
