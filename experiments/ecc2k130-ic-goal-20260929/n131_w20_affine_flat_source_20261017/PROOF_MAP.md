# Proof map: all-valid affine-flat source construction

| Result | Exact hypotheses and statement | Verification status |
| --- | --- | --- |
| Translation-candidate recurrence | In a commutative additive group, a translation preserves every point of `S∪(S+v)` exactly when it preserves every point of `S` and does so again after translation by `v`. | `FlatCandidate.candidate_extend` in [FlatCandidate.lean](FlatCandidate.lean) proves the finite-list form under a commutative-ring addition. Pinned Lean 4.34.1 built it; [lean_check.log](lean_check.log) reports only `propext`, `Classical.choice`, `Quot.sound`. The first failed proof attempt is preserved in `lean_attempt1.log`. |
| Bitmap extension implements the abstract recurrence | 19-bit XOR space, frozen W20 validity bitmap, independent direction outside the existing span | [flat_search.py](flat_search.py) and [cover.py](cover.py) use `C & C[index XOR v]`. [verify.py](verify.py) independently recounts candidate translations for a saved flat, checks direction independence, every discovered flat's exact codes, and every cover block against the bitmap. A fully formal Lean bridge from the bitmap bytes to the particular code set remains open. |
| XOR autocorrelation | `C(v)=Σ_x 1_V(x)1_V(x XOR v)`; binary Walsh–Hadamard transform diagonalizes XOR convolution | [autocorr.py](autocorr.py) computes all 524,288 entries and checks `C(0)=|V|`, `Σ_v C(v)=|V|²`, and even nonzero-shift counts. [verify.py](verify.py) directly recounts the top twenty from raw bitmap bytes. A faithful Lean Walsh-transform theorem remains open. |
| Flat-cover cardinality | Each saved dimension-four flat has 16 codes; the union of `k` such flats has at most `16k` codes | Written proof in [RESULT.md](RESULT.md) is the finite-set union bound. The empirical [cover ledger](cover_blocks.jsonl) is independently replayed in [verification.json](verification.json). The `8,253` threshold is a conditional ideal for a full 132,045-code cover, not a measured cover size. |

The source pilot is target independent. Its 16-code blocks must next be coupled to an exact public-target predicate and verified on an unpinned N41 relation before they can support the frozen N131 ordinary-relation attempt. The full curve-to-factor-base and target-DLP formalization obligations remain open.
