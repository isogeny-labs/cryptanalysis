# Sign and source-label proof map

`SignLift.target_reachable` is a checked Lean 4.34.1 theorem for an arbitrary type with an addition and involutive negation satisfying `−(x+y)=−x+−y`. It defines a finite binary tree whose leaves admit both signs, and whose internal claimed point class is that of the sum or difference of the child classes. It proves that every compatible root point, including either sign of its class, is reachable by choosing leaf signs. The theorem preserves the tree and target quantifiers; it does not assume the claimed root is reachable. `lean SignLift.lean` builds it and `#print axioms` reports no axioms. The first missing-Mathlib attempt and second proof-shape error remain in the two attempt logs.

The finite N41 bridge is `audit.py` and `audit_sage.py`. For each of seven slots and 40 source codes, the table has two distinct raw x roots, each with precisely two raw points related by `(x,y)↦(x,y+x)`. All 1,120 stored pair states were independently rebuilt from the 160 signed unrotated source leaves with the checked Sage launcher, including their raw sums, fourfold subgroup projections, and pair output coordinates. `audit_formula.py` rebuilt the frozen public XCNF byte-for-byte and verified every one of the 966 cross-slot source-code conflict clauses. The source code determines the pair's folded-column labels uniquely, so the formula already tests label collisions.

The remaining mathematical bridge is the exact equivalence, on the nonexceptional reciprocal chart, between each encoded S3 edge and the `classEq` sum-or-difference condition in the Lean theorem. That curve-specific S3 equivalence is not formalized here. The proof therefore establishes the structural sign-lift implication under an explicit edge-semantics hypothesis; the finite audit establishes sign closure and label completeness for the named source table. It does not claim that adding redundant sign variables could never change SAT heuristics, only that these signs and labels supply no additional exact rejection condition under the stated S3 semantics.
