# The seven-pair source is sign-closed and its label conflicts are already encoded

The fixed-seed N41 seven-pair source has **40 codes per slot, two coordinate roots per code, and both point signs for every root**. The source code also fixes both folded columns. Across seven slots, there are 46 conflicting ordered code pairs for each of 21 slot pairs, and the frozen public XCNF contains all **966** resulting exclusion clauses. A checked-Sage replay reconstructed all 1,120 signed pair states from archived leaves and matched their raw sums, cofactor-four projections, and output coordinates. This result closes the proposed upper-link sign/label rejection route for this exact source: under the usual nonexceptional S3 edge semantics, every coordinate-tree assignment that obeys the existing code-conflict clauses admits a consistent leaf-sign lift to either target point sign.

The field is `GF(2)[t]/(t^41+t³+1)`, curve `y²+xy=x³+1`, curve ID `EC1N41Ckb1h7d5e80d3c4d0`, fixed seed code 56, rotations `(0,6,12,18,24,30,36)`, public subgroup point `(1654986373106,1310318707590)`, and selected raw target `(2026560328086,1928332930914)`. This is the same public point and source law as the preceding functional-root SAT query. The source is a point-decomposition component with `candidate_id: null`.

The independent Sage run used the checked repository launcher and frozen input/source hashes, one worker, a 600 s parent wall cap, and 4 GiB RSS cutoff. It completed in **98.705 s** with status `EXIT_0`, empty stderr, and all 1,120 states checked. The RSS monitor was degraded; its 240,304,128-byte sample is descriptive, not a certified peak. The formula audit regenerated the exact 1,465,908-byte public XCNF with SHA-256 `125db65bca49ee03e6bc705509f7bfeb2d9db86d2a3b0534cfd1f30cbc6c5c7e`, 30,536 variables, 67,329 clauses, and 8,439 native XOR rows. It found every expected label clause in that formula. Run `python3 -B verify.py` for the frozen receipt check.
