# A target-conditioned third-code gate selects the ordinary N41 relation before sign expansion

For the archived ordinary N41 public point, a three-code prefilter retained exactly one candidate among 38,874 admissible first-three-code families when the four-state suffix of its verified relation was fixed. The retained codes `(24,37,10)` led to raw state IDs `(97,151,42)` and an independently replayed full group sum. Across 32 seeded valid suffix controls, the same gate retained zero candidates. The [producer](result.json) and [independent checked-Sage audit](audit_result.json) agree on every panel and all `5,293,896` coordinate membership slots.

The curve is `EC1N41Ckb1h7d5e80d3c4d0` over `GF(2)[t]/(t^41+t³+1)`, with `y²+xy=x³+1`, subgroup order `549756390943`, and cofactor four. The archived public point is `Q=(1458168294740,1672312028033)` from the ordinary scalar-input law seeded `202609291700`. The fixed W8 seed is 56, with 40 source product codes and four signed states per slot. The first two slots' 1,554 admissible code-pair coordinate families were independently audited in the preceding [two-code study](../n41_w8_two_code_affine_span_20261013/RESULT.md). Both stages use `candidate_id: null` because they are component measurements.

The gate builds each first-two-code affine span once. For a four-state suffix, it subtracts those four group points from the raw target. For each third-slot code, it subtracts each of that code's four states, then checks whether the reciprocal coordinate of the residual lies in a first-two-code affine span. A code triple with no such state is rejected before expanding its first two codes' 16 signed-state combinations. Exact coordinate membership and full point addition check the survivors. Cross-slot folded-column conflicts are removed before membership tests. [PROOF_MAP.md](PROOF_MAP.md) records why the affine screen preserves every exact coordinate match and how the finite group calculation was audited.
