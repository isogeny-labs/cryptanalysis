# Native N131 quartic/subspace filter with batch inversion

An exact native `GF(2^131)` quartic/subspace filter classified **1,048,576 consecutive first codes** for the frozen public raw-point two-pair query in **7.204 seconds** of query-stage worker time. It matched **all 258** independently classified checked-Sage cases, including the constructed positive first-code family, and passed 100 additional planted-subspace-root controls. A 1,024-code batch inversion and ARM64 carryless multiplication reduced the per-code cost of the prior Sage GCD stage. The measured prefix is a stage result: the projected source-valid W29 first-code count alone would take about **469 seconds** at this rate for one fixed two-pair query, before generating or filtering that source list and before the other pair slots in the full relation search.

## Exact instance and gate

The field is `GF(2)[u]/(u^131+u^13+u²+u+1)` on `y²+xy=x³+1`, curve ID `EC1N131Ckb1heb5f1998f20b`. The W29 restriction of the frozen W33 source has seed mask `898618`, 28 free bits, and pair rotations 0 and 18. The [input table](input_extended.tsv) pins the 13-term bidegree-(4,4) eliminant coefficients for the constructed positive point and frozen public raw point, plus 258 Sage-classified first-code cases. The known positive pair codes are `(3,16722)`; the native program independently checks that their products satisfy the eliminant and that the right product lies in the declared 28-dimensional subspace.

For fixed first product `p`, specialize the eliminant to `H_p(Z)` of degree at most four. The right-product subspace has linearized vanisher `L_V(Z)=Σ_{i=0}^{28} c_i Z^(2^i)`, constructed by the exact basis-adjunction recurrence. Reduce `L_V` modulo the monic normalization of `H_p`. Multiplication by that remainder in `GF(2^131)[Z]/(H_p)` has a matrix of size at most four. Its determinant is nonzero exactly when the quartic and subspace vanisher are coprime, so a zero determinant retains the first-code family. The implementation handles lower-degree and zero-polynomial specializations separately. It verifies each supplied leading-coefficient inverse by multiplication before use.

The [native source](native_batch.cpp) uses the pinned ARM64 `PMULL` field kernel, a 17-byte-position squaring table, and a 1,024-code Montgomery batch inversion. The source product `a²+sa` and Frobenius rotation are binary-additive, so a prefix XOR updates consecutive first-code products without field multiplication. The [Lean proof map](PROOF_MAP.md) covers these structural identities and the batch inverse certificate; the concrete determinant and field bridges are audited by Sage and native controls.

## Frozen controls and measured stages

The [checked-Sage reference](reference_result.json) classified both target rows for first codes `0..127` and `16722`, 258 cases total, in 28.077 seconds. It found one unresolved first family, `(constructed target, first code 3)`, with GCD degree one; every other case had GCD degree zero. All three native binaries matched the 258 decisions before scanning the public first-code prefix. The [unit receipt](unit_frozen.stdout) passed 200 each of multiplication, square, and inverse comparisons against the portable field implementation, then preserved 100 independently constructed right-subspace roots; all 100 single-bit-altered controls were rejected.

Each run used one native process with a frozen 120-second wall cap and a process-checked 4-GiB RSS cap. The scan includes quartic specialization, batch inversion where applicable, right-subspace reduction, determinant, and all 1,048,576 decisions. It excludes process launch, input loading, reusable subspace construction, and the 258-case control check; those costs are retained separately in each stdout receipt. The runs used an ordinary shared host, so differences among compiler builds are descriptive stage measurements. `clang++ -O2` and `-O3` crashed in the frontend on the frozen batch source; [compiler receipts](compiler_probe.json) preserve both failures. The successful optimized build disables vectorization while leaving inlining enabled.

The 1,048,576 scanned codes are **raw first-code assignments**. The observed zero unresolved families applies exactly to that public two-pair prefix. The prior 65,536-mask source sample contained 16,677 eligible pairs; applying that fraction to `2^28` codes projects 68,308,992 eligible first codes. At 7.204 seconds per `2^20` codes, a serial pass over the projected eligible list would take about 469 seconds, while all `2^28` raw codes would take about 1,844 seconds. These are rate projections, not completed population counts or full target-query timings. Preparing the eligible list and searching the remaining pair slots still have to fit the one-worker 600-second gate. The complete IC method remains unresolved, so every stage artifact retains `candidate_id: null`.

## Next experiment

The arithmetic bottleneck for a **single fixed two-pair query** is now near the requested envelope when restricted to a precomputed eligible list. The next useful algorithmic test must share this filter across many target-derived residuals or reject families of the other three pair slots before invoking it. It should first reproduce an unpinned N41 ordinary five-pair relation with full source and column checks, then freeze the corresponding N131 public-point search and account for every attempted residual, eligible-code preparation, native query, and independent point replay. The final goal remains one previously unseen target DLP with verified online wall below same-point rho under the repository isolation contract.
