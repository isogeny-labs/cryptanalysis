# Protocol: walk count of the k0n53 walked descent

**Status:** frozen 2026-11-04, before any data. **Class sought:** engineering
(the algorithm and its verified outputs are the same; the probe order changes).
**Repository:** `aburan28/cryptanalysis`, production Rust crate `suite/`.

## Question

`IndividualLogSolver::solve_by_walking` steps `W` walks together and shares one
field inversion per round across their slopes (Montgomery's trick). `W` is
fixed at 64 on `main`.

Does a wider batch, `W ∈ {128, 256, 512}`, lower the cost of a verified k0n53
m = 2 descent?

## Why the answer is not just a speedup measurement

The probe sequence `[a]G + [b]Q` depends on `W`: the walk starts and their
order of visit change. So does the trial on which the first decomposition is
found, and the relation that is found.

- The logarithm does not change. It is verified as `[d]G = Q` inside the
  solver, and checked here against the scalar the target was made from.
- Every probe is a uniform point of the subgroup whatever `W` is, so the
  expected number of trials is the same for every arm.
- So the expected cost of a descent is `E[trials] × cost per trial`. The arms
  can differ only in cost per trial, plus the work after a success:
  - at most one round's keys, `W − 1` of them;
  - the start-up, three scalar multiplications plus `W` affine additions.

  Both of these are inside the measured wall time.

## Instance (fixed)

- **Curve:** the perfbench k0n53 rung (`suite/examples/perfbench/relation.rs`,
  `k0n53`). It is `KoblitzCurve::subfield(1, 53, 0, 1)`, with subgroup order
  21,044,858,204,113.
- **Factor base:** `build_subgroup_orbit_factor_base(c, 1, 15_000)`.
- **Pair table:** `PairSumTable::build_folded_within` at its default budget.
- **Collection:** m = 3, window 477, aimed, seed 1, units of 2048 trials
  until the logs solve.
- **Descent:** m = 2, `max_trials` 20,000,000, `allow_direct_relation` false.
- **Driver:** `suite/examples/descent_walks.rs` at the commit that adds this
  protocol, built `--release`, with the same binary for every arm.

## Held-out targets

- **Targets:** 256. Target `i` takes seed `s = 5000 + i`.
- **Scalar:** `k = StdRng(s ⊕ 0x534f4c5645525447).gen_range(1..r)`, the same
  rule as perfbench `Target::Random`.
- **Point:** `Q = [k]G`.
- **Disjoint from perfbench:** the seeds are generated by the driver at run
  time. Perfbench uses seeds 100–131.
- **Pilot:** a smoke run of the driver on seeds 1–4, before the measured run,
  only checks that it executes. It is reported, and it is not data.

## Arms and order

- **Arms:** `W64a`, `W64b` (the A/A pair), `W128`, `W256`, `W512`.
- **Rounds:** 3.
- **Order:** within each round, the arm order is a shuffle drawn from
  `StdRng(20261104)`. Every arm descends all 256 targets in seed order.
- **Run conditions:** single thread, `taskset -c 3`, on the session VM
  (L0: shared 4 vCPU, no PMU, descriptive wall).
- **Command:**

  ```
  descent_walks --walks 64,64,128,256,512 --targets 256 --target-seed 5000 --rounds 3 --order-seed 20261104
  ```

## Measurements

One JSON line per (round, arm, target) records:

- `walks`, `seed`;
- `solved`;
- `verified` (the returned `d` equals the target's `k`);
- `trials`;
- `ns` (wall time of `solve`).

## Analysis (fixed before data)

1. **Validity.**
   - Every row must be `solved` and `verified`.
   - Any unverified or unsolved row invalidates its arm, and is reported.
2. **Primary metric: cost per trial.**
   - Per arm and round, `c = Σ ns / Σ trials` over the 256 targets.
   - Pool the three rounds per arm (sum `ns` and sum `trials`).
   - **Ratio** `ρ_W = c(W64a ∪ W64b) / c(W)`: above 1 means cheaper.
   - **95% CI:** 10,000 bootstrap resamples of targets, paired, resampling a
     target with all its rows. Seed 1.
3. **Noise floor.**
   - `ρ_AA = c(W64a) / c(W64b)`, with its CI, by the same bootstrap.
   - Its half-width is `h_AA = max(|ρ_AA − 1|, CI half-width)`.
4. **Secondary metrics.**
   - **Per-descent wall:** mean `ns` per verified target, as a ratio to `W64`
     with a bootstrap CI.
   - **Trial distribution:** mean trials per arm, as a ratio to `W64` with a
     CI. This is a check that the trial distribution is unchanged; the
     prediction is a ratio of 1.
   - **Instructions:** Callgrind Ir per trial on the first 8 targets, 1
     round, every arm (scalar paths; deterministic).
5. **Decision.**
   - **Selection:** let `W*` be the arm with the largest `ρ_W` among 128,
     256 and 512.
   - **Adopt:** `W*` becomes `IndividualLogSolver::DEFAULT_WALKS` if the
     lower end of its CI exceeds `1 + h_AA` and its per-descent wall ratio
     CI does not lie wholly below 1.
   - **Keep 64:** otherwise.
   - **Recording:** either outcome is recorded. A null result is a valid
     result, not an improvement.
6. **Consequence of adopting.**
   - Probe order changes, so perfbench fingerprints of the walked-descent
     kernels change (`relation/koblitz_descent_k0n53_m2_x4`, and the
     descent phase of `relation/koblitz_rung_k0n31`). That is expected and
     is reported.
   - Every logarithm still verifies.

## Claim limits

- A per-trial cost ratio on one curve and one host (L0). It is not a
  complete-solve `S`, and it makes no matched-rho claim.
- This is the descent phase only. Collection and linear algebra are
  untouched.
