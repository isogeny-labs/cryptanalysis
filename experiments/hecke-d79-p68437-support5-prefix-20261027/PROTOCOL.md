# Retrospective p68437 support-five source-prefix experiment

`inputs.json` pins the prospectively selected p68437 class, all 40 source fibers, support-at-most-four relations, complete support-five candidate sets, audits, source code and degree-13 function artifact. The question is how many source fibers the existing ascending and projection round-robin orders need before the support-five outside-trace rows make the rational 40-column relation matrix full rank. The full 40-source result was already known before this protocol, so source counts are retrospective scheduling results, not holdout predictions.

For each order, freshly load the pinned degree-13 functions in a checked Sage process with `H.build` prohibited. Lift sources one at a time, independently check each fiber against the hash-pinned full receipt, and enumerate all signed support-five cancellations among visited sources by a pair–triple index. Require five distinct source indices, canonical first sign `+1`, and verify every candidate as a class-point row. Compare the candidate set at every prefix with the frozen full-census subset. Preserve every zero-yield and failed prefix. Compute rational and mod-109 ranks for two baselines in the same replay: (1) all degree-2/5, direct support-at-most-four and Hecke support-at-most-four rows; (2) that baseline plus all verified direct support-five rows. Stop when both reach rational rank 40 or after 40 sources. The source lifting, repeated index construction, candidate checks and rank recomputation are charged to each order's measured run.

An independent auditor must derive the first-hit counts and every prefix rank from the hash-pinned candidate hypergraph and exact row matrices with a different implementation. It must verify the fresh replay's source order, candidate counts, rank path, and all retained statuses. Save `./sage --runtime-info` before measured Sage work and cap each Sage job at 1,800 seconds. `candidate_id` and target-online time remain null.
