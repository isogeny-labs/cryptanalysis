## Entry points

The constructor and alias feed the existing catalog inspection and estimation
interfaces in both repositories. The companion [ecbench-curve.json](ecbench-curve.json)
is an exact `prime_explicit` CurveSpec for crypto's ecbench `workloads.curves`
array. Retain `targets_per_curve: 1` for each single-target workload. It uses
the supplied equation and generator without searching for a replacement curve.
A target may be generated by the existing harness from its frozen target seed.
[pcc:unverified]

`icx run` currently runs bounded size analogues; selecting `s56` there does
not constitute an exact S56 execution. Exact IC runs use the explicit ecbench
fixture and an applicable method configuration. No measured IC candidate,
factor base, relation archive or performance row is introduced here.

## Arithmetic witnesses and correction

The native checks test deterministic 64-bit primality, nonsingularity,
G on the curve, [n]G = O, and the Hasse interval. Since G is nonzero and n is
prime, n divides the group order. The interval contains only one multiple of n,
which determines the stated order. These remain producer arithmetic assertions
until the independent PCC gate admits them. [pcc:unverified]

The twist order is `71776123223343867 = 27 * 2658374934197921`; its large
prime factor has **52 bits**. The Frobenius discriminant is
`t^2 - 4p = 9 * (-29937824829444491)`, with t = -132906245. The negative
factor is fundamental, giving Frobenius-order conductor 3. [pcc:unverified]

The native polynomial-product witness checks that the 3-division polynomial
`3x^4 - 18x^2 + 12bx - 9` has four distinct rational roots. Their curve
right-hand sides are nonsquares: the rational objects are cyclic kernels,
not four rational affine 3-torsion points. With Frobenius conductor 3,
these four rational kernels place this model on the 3-volcano **surface**;
conductor 3 alone does not establish the floor. This uses the depth-one
criterion documented in crypto's `docs/curves/ic/README.md`. [pcc:unverified]

The source catalog leaves End(E), conductor and volcano-level certification
fields null pending independent admission. This avoids promoting native
self-checks into a signed or Lean result. Full formalization of the ordinary
volcano implication is not supplied by this integration. [pcc:unverified]
