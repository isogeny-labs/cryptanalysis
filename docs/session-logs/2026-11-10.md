### Decisions made (and why)

- Standard library only: the scanner must run on the hosts it audits (bastions,
  KDCs, appliances' management jump hosts) where `cryptography`/`pyyaml` are
  not installable; `openssl`, `ssh-keyscan`, `klist`, `gpg`, `certutil` are
  optional accelerators with pure-Python fallbacks.
- Collectors never grade; all thresholds live in `policy.py` with stable rule
  ids and four profiles, so a profile change is a re-grade of the saved JSON
  inventory, not a rescan (`cryptoscan report result.json --profile cnsa2`).
- Trust-anchor self-signatures with SHA-1/MD5 are INFO (relying parties do not
  verify a root's self-signature); the root's key size is still graded.
- Post-quantum exposure is reported per asset (`PQC-TRANSITION`) with the NIST
  IR 8547 timeline (deprecate 2030, disallow 2035) rather than one finding per
  RSA/EC key, to keep the report readable; CNSA 2.0 profile makes non-PQ key
  exchange a MEDIUM.
- Active probes are handshake-only (SSH KEXINIT, TLS ClientHello, optional
  SNMP sysDescr GET behind `--snmp-probe`); never authentication. Community
  strings, password hashes and key bytes are never written to the report.
- Conductor is not installed in this web session (`which conductor` empty, no
  `.conductor/`); per docs/CONDUCTOR.md the hooks warn and let edits through.
  Scope: `tools/cryptoscan/**`, `.github/workflows/cryptoscan.yml`, this log.

### Errors (what went wrong, how it was handled)

- `openssl req -x509` on OpenSSL 3 adds `CA:TRUE` by default, which made a
  "leaf" fixture a CA; regenerated the fixtures with explicit
  `basicConstraints=CA:FALSE`.
- PBES1 (`PBE-MD5-DES`) PKCS#8 fixture needed `-provider legacy`; generated
  that way so the legacy-PBE detection has a real fixture.
