\textbf{2026-11-15. Native implementation and correctness; timing prospective.}\\
All outcomes below are producer observations. No signed independent verification or measured frontier claim. [pcc:unverified]

The new \texttt{subtract-binary-batch} oracle uses the actual FastCurve backend in both \texttt{isogeny-labs/crypto} and \texttt{isogeny-labs/cryptanalysis}. It caches negative operands, reuses scratch and the base's indexes, and defers ordinate completion until the abscissa filter admits a candidate. Existing CLMUL/available SIMD dispatch is reused. The previous tiny-field complete-relation checker remains unchanged.

\textbf{Usage:} both IC CLIs accept
\begin{verbatim}
--oracle subtract-binary-batch:m=2,block=32,lazy=1
\end{verbatim}
Crypto also registers it in ecbench. m must be 2; block is 1..4096; lazy is 0 or 1; unknown parameters fail. Default block 32 is provisional until timing. This is a first-hit workload, not complete relation enumeration.

\textbf{Concrete OpenSSL 3.5.7 edge case.} On
$y^2+xy=x^3+1$ over GF(128), modulus 131, raw \texttt{EC\_POINT\_invert} leaves $(1,0)$ unchanged. The primary \href{https://github.com/openssl/openssl/blob/openssl-3.5.7/crypto/ec/ec2_smpl.c}{ec2\_smpl.c} inversion returns early for Y=0. The correct negative is $(1,1)$. The raw API is preserved under \texttt{--check-native-invert}; matched \texttt{--check} applies affine negation with OpenSSL BN field addition, then uses EC\_POINT\_add. This bounded control is not a statement about every point or standard subgroup. [pcc:unverified]

For a base containing only $(1,0)$ and targets $(0,1),O$, the raw API reports no witness then $(0,0)$; the corrected control reports $(0,0)$ then no witness. Raw output and the initial cross-backend mismatch are retained. The matched external helper has no timer. [pcc:unverified]
